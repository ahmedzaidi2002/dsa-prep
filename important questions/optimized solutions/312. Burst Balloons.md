# 312. Burst Balloons — Understanding the Recurrence

https://leetcode.com/problems/burst-balloons/

## The confusion

The recurrence is:

```
dp[i][j] = max over k in [i, j] of:
    dp[i][k-1] + dp[k+1][j] + arr[i-1] * arr[k] * arr[j+1]
```

where `k` is the **last** balloon burst in the range `[i, j]`.

The confusing part: `dp[i][k-1]` is *itself* the subproblem of bursting
balloons `i..k-1` — so while computing it, those balloons are still there.
But the gain term `arr[i-1] * arr[k] * arr[j+1]` treats `i-1` and `j+1` as
already neighbours of `k`, as if `i..k-1` and `k+1..j` are already gone.
Both feel true at once, which feels like a contradiction.

## The fix: separate "what dp[i][k-1] computes" from "when it happens"

`dp[i][k-1]` is not a *live event on a timeline*. It is a **number** — the
best possible total score obtainable from popping all balloons in range
`[i, k-1]`, assuming `i-1` and `k` are the walls on either side the whole
time that subproblem runs.

It doesn't matter *when* in real time those pops happen, only that:
- Balloons outside `[i, k-1]` (specifically `i-1` and `k`) are not touched
  during that subproblem.
- So `i-1` and `k` act as fixed walls for the entire `dp[i][k-1]` process.

## Walk through the timeline, explicitly

Think of `k` as **fixed and burst last** among `{i, ..., j}`. Before `k`
pops, here is the actual state:

**Phase 1 — before anything in `[i, j]` happens:**
Balloons `i-1` and `j+1` are the fixed boundary walls (already burst or
outside the range, doesn't matter — they're just markers). All of
`i, i+1, ..., j` are still present.

**Phase 2 — run the left subproblem `dp[i][k-1]`:**
This bursts all balloons `i..k-1`, in whatever optimal order that
subproblem finds — but it never touches `k`. So during this phase, the
right wall for this sub-range is `arr[i-1]` on the left and `arr[k]` on the
right (since `k` hasn't popped yet, it's still standing there as a wall).
That's *exactly* the boundary the subproblem `dp[i][k-1]` assumes — `i-1`
and `k` are its walls. Good, matches.

**Phase 3 — run the right subproblem `dp[k+1][j]`:**
Same idea — bursts `k+1..j`, using `k` (still standing) and `j+1` as its
walls. Order relative to phase 2 doesn't matter, they don't interact.

**Phase 4 — now only `k` is left in `[i, j]`. Burst it:**
At this exact moment, everything in `i..k-1` and `k+1..j` is already gone
(phases 2 and 3 finished). So `k`'s only remaining neighbours are `i-1`
and `j+1` — the outer walls. That's why the gain is
`arr[i-1] * arr[k] * arr[j+1]`.

## Why there's no contradiction

The key realization: **`dp[i][k-1]` and `dp[k+1][j]` are computed as
independent, self-contained subproblems that happen entirely *before* `k`
is popped.** Inside those subproblems, `i-1` and `k` (or `k` and `j+1`) are
just the boundary walls — they are never burst by that subproblem, only
used as multipliers.

So at no single point in time do you simultaneously believe "these
balloons still exist" and "these balloons are gone." The timeline is
strict:

```
[ burst i..k-1 optimally, using i-1 and k as walls ]   <- dp[i][k-1]
[ burst k+1..j optimally, using k and j+1 as walls ]   <- dp[k+1][j]
[ finally burst k, its only neighbours now are i-1, j+1 ]  <- gain term
```

The trick that makes this work is choosing `k` as the **last** balloon to
pop in `[i, j]`, not the first. That's what guarantees `k` is still
standing (as a wall) while `i..k-1` and `k+1..j` get resolved, and that
`i-1`/`j+1` are `k`'s only neighbours by the time `k` finally pops.

## Standard Code

```cpp
class Solution {
public:
    int maxCoins(vector<int>& nums) {
        int n = nums.size();
        vector<int> arr(n + 2, 1);
        for (int i = 0; i < n; i++) arr[i + 1] = nums[i];

        vector<vector<int>> dp(n + 2, vector<int>(n + 2, 0));

        for (int len = 1; len <= n; len++) {
            for (int i = 1; i + len - 1 <= n; i++) {
                int j = i + len - 1;
                for (int k = i; k <= j; k++) {
                    dp[i][j] = max(dp[i][j],
                        dp[i][k - 1] + dp[k + 1][j] +
                        arr[i - 1] * arr[k] * arr[j + 1]);
                }
            }
        }

        return dp[1][n];
    }
};
```

## Time & Space Complexity

**Time:** O(n^3) — O(n^2) intervals `[i, j]`, each trying O(n) choices of `k`.

**Space:** O(n^2) — dp table over all `[i, j]` ranges.
